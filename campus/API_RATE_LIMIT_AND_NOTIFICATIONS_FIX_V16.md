# Campus Portal v16 — API Storm + Notification Center Fix

## API/request storm fixes
- Increased the normal API budget to avoid false site-wide throttling under ordinary portal activity.
- Shared GET storage/sync reads are excluded from the generic API limiter because they are idempotent read operations and are now client-deduplicated/cached.
- Added same-page GET request coalescing and short TTL caching for `/api/storage/kv` and `/api/storage/kv/list`.
- `remoteGet()` and `remoteList()` now reuse in-flight requests instead of sending duplicates.
- Remote realtime polling was reduced from 10s to 30s and uses the shared cache.
- Removed the duplicate 20s flash-news polling loop; the existing realtime watcher handles it.
- Removed the 60s AI/ML warm-up interval; warm-up remains timestamp-gated.
- Browser API wrappers no longer retry HTTP 429 responses.
- AI/ML cold-start retries are limited to one short retry for 502/503/504 responses.
- Advanced runtime GET retry logic no longer retries 429 responses.
- Gate-pass background polling was reduced from 10s to 30s to prevent unnecessary API traffic.

## Notifications
- Added a persistent in-portal notification history backed by localStorage.
- Toasts generated by portal actions are now copied into the Notification Center.
- Notification badge includes unread portal notifications in addition to flash news and approval counts.
- Opening the notification center marks both portal notifications and flash news as seen.
- Existing flash-news notifications remain fully supported.

## Compatibility
- No existing portal tabs or feature modules were removed.
- Existing API contracts remain unchanged.
- Login attempt/cooldown logic remains unchanged.
